# NixOS Virtual Machines

Build and run NixOS VMs on macOS using the linux-builder and UTM.

## Architecture

```
macOS (nix-darwin)
├── linux-builder VM        # Lightweight NixOS VM for building aarch64-linux
│   └── Builds disk images via nix
└── UTM                     # Runs the resulting VMs
    └── phantom-tanuki      # NixOS VM (GNOME + KDE, accessibility testing)
```

The linux-builder is a background NixOS VM managed by nix-darwin that acts as a remote Nix builder. It builds aarch64-linux derivations that macOS can't build natively. UTM runs the resulting disk images as full VMs.

## Commands

| Command | Alias | Description |
|---------|-------|-------------|
| `mise nixos-remote-switch -- <host> [target]` | `mise nrs` | Deploy config changes via SSH (fast, seconds) |
| `mise nixos-build-image -- <host> [variant]` | `mise nbi` | Build a disk image only |
| `mise nixos-utm -- <host> [variant]` | `mise nbu` | Build image + create/replace UTM VM (slow, initial setup) |
| `mise nixos-builder-stop` | `mise nbt` | Stop the linux-builder (frees ~16GB RAM) |
| `mise nixos-builder-start` | `mise nbs` | Start the linux-builder |
| `mise nixos-builder-reset` | `mise nbr` | Reset the linux-builder (recreate disk after config changes) |

Examples:
```bash
mise nbu -- phantom-tanuki          # Build image and create UTM VM
mise nbi -- phantom-tanuki iso      # Build ISO instead of qcow2
mise nbr                            # Reset builder after changing its config
```

## Machine configs

NixOS machine configs live in `machines/<hostname>/` like darwin ones. They use `mkNixosHost` in `flake.nix`.

| File | Purpose |
|------|---------|
| `machines/<host>/default.nix` | Machine config (packages, services, desktop) |
| `machines/<host>/hardware.nix` | Hardware/boot config (generated by `nixos-generate-config`, `mkDefault` for image build compat) |
| `modules/nixos/` | Shared NixOS modules (core, graphical) |

## Linux builder

The linux-builder is configured in the darwin host's machine config:

```nix
# machines/procyonid-trailblazer/default.nix
nix.linux-builder = {
  enable = true;
  config = {
    virtualisation = {
      darwin-builder = {
        diskSize = 100 * 1024;  # 100 GB
        memorySize = 8 * 1024;  # 8 GB
      };
      cores = 6;
    };
    nix.settings = {
      min-free = lib.mkForce 0;  # Disable auto-GC (races with builds)
      max-free = lib.mkForce 0;
      auto-optimise-store = true;
    };
  };
};
```

### Resetting the builder

Changing `diskSize` or other builder config requires a full reset after `nix-switch`:

```bash
mise nix-switch          # Apply new config
mise nbr                 # Reset builder (deletes old disk, recreates)
```

The disk image lives at `/var/lib/linux-builder/nixos.qcow2` (sparse qcow2 -- only uses actual written size on disk).

### Starting and stopping

The builder uses ~16GB RAM and runs 24/7 by default. Stop it when not needed:

```bash
mise nbt    # stop (frees RAM)
mise nbs    # start (needed before nbi/nbu/nrs)
```

The `nrs`, `nbi`, and `nbu` tasks do not auto-start the builder -- you'll get a build error if it's stopped.

### Builder GC

Auto-GC is disabled on the builder to prevent it from deleting store paths mid-build (the default `min-free=1GB` caused race conditions). The `nbi` and `nbu` tasks run `nix-collect-garbage` on the builder before each build instead.

## UTM VM setup

The `mise nbu` task automates:
1. Build the disk image via linux-builder
2. GC the builder's store
3. Delete existing UTM VM (if any)
4. Create new UTM VM via AppleScript (display, serial, networking)

### VM access

- **Display**: UTM window (virtio-gpu-gl-pci)
- **Serial**: UTM serial console (ptty, built-in terminal)
- **SSH**: `ssh -i ~/.ssh/nixos-vm avi@phantom-tanuki.local` (mDNS via Avahi)
- **IP lookup**: `osascript -e 'tell application "UTM" to query ip of virtual machine named "phantom-tanuki"'`

### SSH key setup

A dedicated deploy key (`~/.ssh/nixos-vm`) is used for VM access. Generate with:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/nixos-vm -N "" -C "nixos-vm-deploy"
```

The public key is configured in `machines/<host>/default.nix` via `openssh.authorizedKeys.keys`.
For initial bootstrap, copy the key manually: `ssh-copy-id -i ~/.ssh/nixos-vm avi@<host>.local`

### Display card

Use `virtio-gpu-gl-pci` (GPU-accelerated). `virtio-ramfb-gl` has a mouse cursor bug where it disappears in the right third of the screen.

## Typical workflow

1. **First time**: `mise nbu -- phantom-tanuki` (builds image, creates UTM VM, ~10 min)
2. **Config changes**: `mise nrs -- phantom-tanuki` (pushes changes via SSH, ~6 sec)
3. **Full rebuild**: Only needed if you break the VM or want a clean slate

## Known limitations

- **Clipboard sharing**: Doesn't work with `virtio-gpu-gl-pci`. SPICE vdagent needs a SPICE display channel which this card doesn't provide.
- **Image copy**: Each `nbu` run copies the ~21GB qcow2 to `/tmp` because AppleScript can't access `/nix/store` paths. Takes ~10s on fast storage.
- **Rebuild time**: Full image builds take ~9 minutes. Incremental changes still rebuild the full image (no delta updates).
- **Bootstrap**: First `nrs` deploy requires manually setting `trusted-users` on the VM or copying SSH key with `ssh-copy-id`. After first successful deploy, the NixOS config persists these settings.
